# TCP vs UDP

포트 공부하다가 이어서 TCP/UDP를 봤다. 포트를 실제로 쓰는 게 이 둘이다.

## 위치부터

IP는 목적지 컴퓨터까지 데이터를 보내주는 역할인데, 딱 거기까지다. 제대로 도착했는지, 순서가 맞는지는 신경 안 쓰고 그냥 던진다. 그 위에서 "어떻게 보낼지"를 정하는 게 TCP랑 UDP다. (전송 계층)

## 한 줄 차이

- TCP = 연결형. 확실하게 주고받는다. 상대랑 먼저 연결 맺고, 빠진 거 있으면 다시 보내고, 순서도 맞춰준다. 대신 느리고 무겁다.
- UDP = 비연결형. 일단 던진다. 연결 확인도 재전송도 안 한다. 빠지든 순서 꼬이든 신경 안 쓴다. 대신 빠르고 가볍다.

비유하면:

- TCP = 등기우편 / 전화. "받았어?" "어 받았어" 확인하면서 주고받고, 하나라도 안 오면 다시 보낸다.
- UDP = 편지 우체통에 그냥 던지기 / 확성기로 방송. 도착했는지 확인 안 하고 그냥 쏜다.

## TCP는 연결을 3-way handshake로 맺는다

TCP는 데이터 보내기 전에 악수 세 번을 한다.

```
클라이언트          서버
    |   SYN   →      |   "야 연결하자"
    |   ← SYN-ACK    |   "그래, 나도 준비됨"
    |   ACK   →      |   "오케이 시작"
    |                |
    | ←── 데이터 ──→ |   이제 주고받기
```

이 악수가 끝나야 실제 데이터가 오간다. UDP는 이거 없이 그냥 바로 쏜다.

## TCP가 "정확"을 어떻게 보장하냐

- 순서 번호: 조각마다 번호 붙여서 순서 맞춰 조립
- ACK + 재전송: "받았어(ACK)" 안 오면 다시 보냄
- 흐름/혼잡 제어: 상대가 감당할 만큼, 회선 막히면 속도 조절

UDP는 이런 거 다 없다. 그래서 헤더도 작고 빠르다.

## 언제 뭘 쓰냐

기준은 하나다. 데이터가 정확해야 하나(TCP), 빠른 게 우선이고 조금 손실 OK(UDP)?

| | TCP | UDP |
|---|---|---|
| 성격 | 정확·신뢰성 | 빠름·가벼움 |
| 연결 | 맺고 시작(handshake) | 그냥 쏨 |
| 재전송/순서 | 보장 | 안 함 |
| 쓰는 데 | 웹(HTTP/HTTPS), 파일전송, 메일, DB, SSH | 실시간 스트리밍, 게임, 음성통화(VoIP), DNS, 방송 |

### 실시간은 왜 UDP냐

화상통화에서 프레임 하나 깨졌다고 "다시 보내줘" 하면, 그거 받는 사이에 이미 그 순간은 지나가 있다. 재전송받아봤자 철 지난 화면이라 쓸모없고 오히려 버벅인다. 그래서 차라리 버리고 다음 프레임 간다. 실시간은 정확함보다 속도/지연이 중요하니까 UDP.

실제 화상통화 앱은 섞어 쓰기도 한다. 연결 맺고 세션 협상하는 신호(signaling)는 정확해야 하니 신뢰성 있는 채널로, 실제 영상/음성은 UDP로. 통짜로 하나만 쓰는 게 아니다.

## TCP로 할지 UDP로 할지 고를 수 있나

고를 수 있는데, 매 요청마다 자유롭게 토글하는 방식은 아니다.

1. 보통은 애플리케이션 프로토콜이 정해놨다. HTTP는 TCP 위에서 돌도록 정의돼 있어서 HTTP 쓰면 자동으로 TCP다. DNS는 기본 UDP고. 프로토콜을 고르는 순간 TCP/UDP도 따라 정해진다.

2. 근데 소켓을 직접 짜면 고를 수 있다. 소켓 만들 때 TCP냐 UDP냐를 코드에서 선택한다.

```java
// TCP
Socket socket = new Socket("192.168.0.130", 8080);
ServerSocket server = new ServerSocket(8080);

// UDP
DatagramSocket socket = new DatagramSocket();
DatagramPacket packet = new DatagramPacket(...);
```

`Socket` 계열이면 TCP, `Datagram` 계열이면 UDP다.

3. 같은 서비스가 둘 다 지원하기도 한다. 그리고 포트는 TCP/UDP마다 따로다. `TCP 53`이랑 `UDP 53`은 다른 거다. DNS가 대표적으로 둘 다 쓴다 (평소 UDP 53, 응답 크면 TCP 53).

그래서 방화벽 정책도 프로토콜을 같이 찍는다.

```
TCP 443 허용   ← 웹(HTTPS)
UDP 53  허용   ← DNS
```

`TCP 80`이랑 `UDP 80`은 별개 규칙이다.

## 참고 - HTTP/3는 UDP 기반

HTTP는 원래 TCP인데, HTTP/3부터는 아예 UDP 기반(QUIC)으로 바뀌었다. TCP의 handshake·재전송이 느려서, 속도 잡으려고 UDP 위에 신뢰성을 새로 얹은 거다. TCP냐 UDP냐는 프로토콜 설계 단계에서 실제로 선택하는 문제다.
