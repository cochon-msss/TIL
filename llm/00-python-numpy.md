# 0단계: 파이썬과 numpy

LLM을 직접 만들어보려고 도구부터 챙겼다. 파이썬은 예전에 잠깐 써봤는데 기억이 안 나서 Java랑 뭐가 다른지부터 다시 봤다. 수학은 오래 안 해서 곱하기, 더하기로만 이해했다.

실습 코드: [code/00_python_numpy.py](code/00_python_numpy.py)

## 파이썬은 Java에서 군더더기를 뺀 것이다

하는 일은 같고 적는 양이 적다.

```java
// Java
public class Main {
    public static void main(String[] args) {
        for (int i = 0; i < 3; i++) {
            System.out.println(i + "번째");
        }
    }
}
```

```python
# Python
for i in range(3):
    print(f"{i}번째")
```

| Java | Python |
|---|---|
| `class`, `main` | 없음. 파일 위에서부터 실행 |
| `int count` | `count`. 타입 안 적음 |
| `{ }` | 들여쓰기. 틀리면 에러 |
| `;` | 없음 |
| `for (int i=0; i<3; i++)` | `for i in range(3)` |
| `i + "번째"` | `f"{i}번째"` |

## 리스트는 번호표 붙은 칸이다

Java의 `ArrayList`다.

```python
tokens = ["나는", "밥을", "먹었다"]
#           [0]     [1]     [2]
```

| 하고 싶은 것 | 파이썬 | 결과 |
|---|---|---|
| 첫 번째 | `tokens[0]` | `"나는"` |
| 마지막 | `tokens[-1]` | `"먹었다"` |
| 앞에서 2개 | `tokens[0:2]` | `["나는", "밥을"]` |
| 개수 | `len(tokens)` | `3` |

"다음 토큰 맞히기"가 리스트로 그대로 표현된다. 앞부분을 잘라서 보여주고 다음 칸을 맞힌다.

```
보여줄 것: tokens[0:2]  → ["나는", "밥을"]
맞힐 것:   tokens[2]    → "먹었다"
```

## 딕셔너리로 토큰에 번호를 붙인다

Java의 `HashMap`이다. 컴퓨터는 글자를 계산 못 하니까 토큰마다 번호를 붙인다.

```python
stoi = {"나는": 0, "밥을": 1, "먹었다": 2}   # 글자 → 숫자
itos = {i: w for w, i in stoi.items()}        # 숫자 → 글자 (뒤집기)
```

처음엔 `stoi`, `itos`가 라이브러리인 줄 알았는데 아니다. 그냥 내가 지은 변수 이름이다. **s**tring **to** **i**nt, **i**nt **to** **s**tring의 줄임말이고 LLM 코드에서 관습처럼 쓴다. 가져다 쓰는 라이브러리는 `import`가 붙는다.

## 컴프리헨션은 for문을 한 줄로 접은 것이다

```python
# 펼친 버전
result = []
for w in tokens:
    result.append(stoi[w])

# 접은 버전 (같은 뜻)
result = [stoi[w] for w in tokens]
```

Java의 `tokens.stream().map(w -> stoi.get(w)).toList()`랑 같다.

## encode와 decode가 LLM 입출력의 뼈대다

자주 쓰는 동작은 함수로 묶는다. `def` 하나면 된다.

```python
def encode(tokens):
    return [stoi[w] for w in tokens]

def decode(ids):
    return [itos[i] for i in ids]
```

```
글자 ──encode──▶ 숫자 ──▶ [ 모델 ] ──▶ 숫자 ──decode──▶ 글자
```

모델은 숫자로 받고 숫자로 준다. 그걸 `itos`로 바꿔서 사람한테 보여준다. 정확히는 숫자 하나가 아니라 "다음은 몇 번일 확률이 몇 %"를 주고 그중 하나를 고른다.

## numpy는 숫자 묶음을 한 번에 계산한다

```python
[1, 2, 3] * 2             # [1, 2, 3, 1, 2, 3]  ← 리스트는 이어붙임
np.array([1, 2, 3]) * 2   # [2, 4, 6]           ← 칸마다 곱함
```

리스트는 계산기로 하나씩 누르는 거고 numpy는 엑셀에서 열 전체를 잡고 ×2 하는 거다. LLM 안은 수백만 개 숫자끼리 곱하고 더하는 거라 for문으로는 너무 느리다. numpy는 안쪽이 C라서 빠르다.

## 2차원 배열은 엑셀 표다

```python
table = np.array([[1, 2, 3],
                  [4, 5, 6]])
table.shape    # (2, 3)  ← 2행 3열
table[1, 2]    # 6
table[0]       # [1, 2, 3]
```

신경망 코드 에러는 대부분 표 크기가 안 맞아서 난다. 막히면 `shape`부터 찍는다.

## 임베딩은 토큰마다 붙인 숫자 한 줄이다

번호표 `0`, `1`만으로는 모델이 아무 의미도 모른다. 그래서 토큰마다 숫자 한 줄을 붙여둔다. 이 한 줄이 그 토큰의 임베딩이고, 모아둔 표가 임베딩 표다.

사람을 `[키, 나이, 활발함]`으로 소개하면 숫자가 비슷한 사람끼리 비슷한 사람인 것처럼, 단어도 비슷하게 쓰이는 것끼리 숫자가 비슷해진다.

```
          음식?   동작?   긍정?        (칸 이름은 설명용)
"밥"   →  [ 0.9,  0.1,   0.5 ]
"빵"   →  [ 0.9,  0.0,   0.6 ]   ← "밥"이랑 비슷
"싫다" →  [ 0.0,  0.3,  -0.9 ]   ← 많이 다름
```

그런데 칸의 뜻은 아무도 정해주지 않는다.

```
처음:  아무렇게나(랜덤) 채움
학습:  다음 토큰을 맞히다가 틀릴 때마다 조금씩 고침
결과:  "밥"과 "빵"은 둘 다 "___을 먹었다"에 나오니까 숫자가 저절로 비슷해짐
```

문장을 encode하고 그 번호로 표에서 줄을 꺼내면 모델에 들어갈 입력이 된다.

```python
emb[encode(["나는", "밥을"])]   # 두 줄을 한꺼번에 꺼냄
```

## 학습은 임베딩만이 아니라 모델 안 숫자 전부를 고친다

처음엔 학습하면 임베딩 숫자가 조절돼서 정확해지는 줄 알았다. 반만 맞다. 모델 안에는 표가 여러 개 있고 그 숫자 전부가 고쳐진다. 이 숫자들을 통틀어 **파라미터**라고 한다. "파라미터 700억 개"가 이 숫자 개수다.

```
토큰 번호 → [임베딩 표] → [계산 표 1] → [계산 표 2] → … → [마지막 표] → 다음 토큰 확률
```

임베딩은 입구에 있는 표 하나일 뿐이다. 그리고 오래 학습한다고 무조건 좋아지지 않는다. 같은 문제집만 풀면 답을 외우듯 모델도 학습 데이터를 외워버릴 수 있다.

## 행렬 곱셈은 같은 칸끼리 곱해서 더하는 것이다

장보기 영수증 계산이다.

```
         사과   우유   빵
개수   [  3,    1,    2  ]
가격   [ 1000, 2000, 1500 ]

3×1000 + 1×2000 + 2×1500 = 8000원
```

가게가 여러 곳이면 가게마다 한 번씩 하면 된다. 그게 행렬 곱셈이다. 새로운 계산은 없다.

```python
count @ prices   # [8000, 7200]  ← A마트, B마트
```

## 행렬 곱셈으로 다음 토큰 후보에 점수를 매긴다

"곱해서 뭘 어쩐다는 거지?"가 제일 궁금했다. 답은 **점수 매기기**다. 모델은 다음에 올 후보 토큰마다 점수를 매기는 기계고, 그 방법이 곱셈이다.

```
              음식 얘기?  사람 얘기?
지금 상황  →  [  0.9,       0.1  ]          ← "밥을" 다음이라 음식 얘기 중

마지막 표:     나는   먹었다   잤다
음식 얘기?  [  0.0,   1.0,    0.0 ]
사람 얘기?  [  1.0,   0.0,    0.5 ]

나는:    0.9×0.0 + 0.1×1.0 = 0.1
먹었다:  0.9×1.0 + 0.1×0.0 = 0.9   ← 1등
잤다:    0.9×0.0 + 0.1×0.5 = 0.05
```

지금 상황과 그 단어가 어울리는 상황이 잘 맞을수록 점수가 크다. 소개팅 궁합 점수 같은 거다.

전체 흐름은 이렇다.

```
"나는 밥을"
  ↓ stoi                    [0, 1]
  ↓ 임베딩 표에서 줄 꺼내기    숫자 줄들
  ↓ 계산 표들 @              문맥을 섞어서 "지금 상황" 한 줄로
  ↓ 마지막 표 @              후보마다 점수
  ↓ 확률로                   나는 10% / 먹었다 86% / 잤다 5%
  ↓ 하나 고르기 + itos        "먹었다"
  ↓ 붙여서 처음부터 반복
```

점수를 확률로 바꾸는 건 실제로는 softmax를 쓴다. 지금은 비율로만 했다. 하는 일은 같다. 점수 높은 게 % 높게.

"확률을 올린다"는 건 학습할 때 얘기다. 정답이 "먹었다"였는데 86%만 줬으면 다음엔 더 주도록 표 숫자를 조금 고친다. 그게 1단계다.
