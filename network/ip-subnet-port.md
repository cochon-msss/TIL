# IP / 서브넷 / 포트

방화벽 정책이 결국 "어느 IP 대역의 어느 포트를 허용/차단하냐" 라서, 이거 제대로 잡으려고 IP·서브넷·포트를 정리했다.

## IP 주소

`192.168.0.130` 같은 거. 네트워크에서 집 주소다. 점으로 나뉜 숫자 4덩어리(옥텟)로 돼있고, 각 덩어리는 0~255다. 각 덩어리가 8비트(`11111111`=255)라서, 4덩어리 x 8비트 = 총 32비트가 IPv4 주소 하나다.

```
192      168      0        130
11000000 10101000 00000000 10000010
```

### 네트워크 부분 + 호스트 부분

IP 하나는 두 부분으로 쪼개진다.

- 네트워크 부분: 어느 대역이냐
- 호스트 부분: 그 대역 안에서 몇 번째 기기냐

아파트로 치면 앞부분이 "동", 뒷부분이 "호수" 같은 거다. 어디까지가 네트워크고 어디부터 호스트인지를 정하는 게 서브넷 마스크다.

## 서브넷 마스크 / CIDR

서브넷 마스크도 32비트인데, 왼쪽부터 1로 채우다가 나머지는 0이다. 1인 자리 = 네트워크 부분, 0인 자리 = 호스트 부분.

```
255.255.255.0
11111111.11111111.11111111.00000000
└──── 네트워크(24) ────┘└호스트(8)┘
```

앞에 1이 24개라서 이걸 `/24`로 쓴다. 이게 CIDR 표기다. **결국 `/N` = 서브넷 마스크에서 왼쪽부터 1의 개수다.** 이거 하나가 핵심.

- 1의 개수(`/N`)가 클수록 → 네트워크 부분 길어짐 → 호스트 부분(0의 개수) 짧아짐 → 대역이 작아짐
- 호스트 비트 수 = `32 - N`
- 한 대역 크기 = `2^(32-N)`

`192.168.0.130/24`를 풀어 말하면 "`192.168.0.0/24` 대역의 130번 호스트" 다.

## 같은 대역인지 판단 (서브넷 계산)

IP를 마스크랑 AND 하면 네트워크 주소가 나오고, 두 IP의 네트워크 주소가 같으면 같은 대역이다. 근데 비트 안 그리고 계산하는 법이 있다.

### 3단계

1. `/N` 보고 블록 크기 구하기: `블록 = 2^(32-N)`
2. 0부터 블록 크기씩 경계 나열
3. 내 IP 마지막 칸이 어느 구간에 드는지 보기 → 그 구간 시작이 네트워크 주소

예) `192.168.1.90/26`

```
1. /26 → 블록 2^(32-26) = 2^6 = 64
2. 경계: 0 | 64 | 128 | 192
3. 90은 64~127 구간
→ 대역 192.168.1.64/26 (범위 .64 ~ .127)
```

블록 크기가 제일 중요한 숫자다. 이거 하나 정확히 구하면 경계, 소속 대역, 호스트 수, 방화벽 범위가 다 딸려 나온다.

### 큰 대역(/24보다 작은 prefix) 꿀팁

`/10` 같은 게 나오면 숫자가 커져서 막막한데, 핵심은 **실제로 쪼개지는 칸(옥텟)은 딱 하나고 그 안 숫자는 128을 안 넘는다** 는 거.

1단계 - 어느 칸에서 쪼개지나

```
/1 ~ /8   → 1번째 칸
/9 ~ /16  → 2번째 칸
/17 ~ /24 → 3번째 칸
/25 ~ /32 → 4번째 칸
```

2단계 - 그 칸 안 블록 크기 = `N을 8로 나눈 나머지`로

```
나머지:  1    2    3    4    5    6    7
블록:  128   64   32   16    8    4    2
```

예) `/10` → 2번째 칸(`/9~/16`), 10 % 8 = 2 → 블록 64 → 2번째 칸이 64씩: `10.0.0.0`, `10.64.0.0`, `10.128.0.0`, `10.192.0.0`

예) `/23` → 3번째 칸, 23 % 8 = 7 → 블록 2 → 3번째 칸이 2씩: `x.x.0.0`, `x.x.2.0`, `x.x.4.0`...

`/26`이든 `/10`이든 결국 "어느 칸에서 몇씩"만 보면 되고, 그 숫자는 늘 작다.

## 특수 주소랑 호스트 수

대역 안 양 끝 두 개는 특수용도라 실제 기기엔 안 준다.

- `.0` (대역 첫 주소) = 네트워크 주소 (대역 자체를 가리킴)
- `.255` 자리 (대역 끝 주소) = 브로드캐스트 (대역 전체에 뿌리기)
- 그래서 실제 쓸 수 있는 호스트 = `블록 크기 - 2`
- 예) `/28`이면 16 - 2 = 14개

## 포트

IP가 어느 컴퓨터냐(집 주소)라면, 포트는 그 컴퓨터 안 어느 프로그램이냐(집 안 창구 번호)다. 한 컴퓨터에서 웹서버도 DB도 SSH도 도니까, IP로 컴퓨터까지 가고 포트로 그 안 누구한테 줄지를 정한다.

```
192.168.0.130 : 443
└─ 어느 컴퓨터 ┘ └ 어느 프로그램 ┘
```

- 포트 번호 범위 0 ~ 65535 (16비트, 2^16)
- 잘 알려진 포트: 22 SSH, 53 DNS, 80 HTTP, 443 HTTPS, 3306 MySQL, 5432 PostgreSQL, 9200 Elasticsearch, 6379 Redis
- 동적/임시 포트(49152~65535): 클라이언트가 접속할 때 그때그때 새로 여는 포트

### 연결은 4개 조합으로 구분된다

```
출발지IP:출발지포트  <->  목적지IP:목적지포트
(클라이언트)              (서버)
```

서버쪽 목적지 포트(443 등)는 고정인데, 클라이언트쪽 출발지 포트(src_port)는 연결할 때마다 임시 포트로 새로 열린다. 그래서 같은 컴퓨터가 같은 서비스에 붙어도 연결마다 src_port가 51001, 51002... 달라진다.

이게 예전에 ES 조회 느렸던 거랑 연결된다. hashkey에 src_port가 들어있어서, 같은 서비스 통신도 연결마다 문서가 쪼개져 폭증했던 거다.

## 방화벽 정책 = IP 대역 + 포트

지금까지 배운 게 다 여기 모인다. 정책은 결국 이 조합이다.

```
출발지 192.168.10.0/24  →  목적지 10.0.0.5  포트 443  허용
     (어느 대역에서)        (어디로)      (무슨 서비스)
```

"어느 대역(IP+서브넷)의, 어느 서비스(포트)를 열지/막을지" 다. 대역을 너무 크게 잡으면(`/16` 같은 거) 필요 없는 IP까지 열려서 보안 구멍이 되니까, 딱 필요한 만큼 잡는 게 중요하다.
