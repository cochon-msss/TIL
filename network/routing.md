# 라우팅

[NAT](nat.md) 노트에서 "사설 IP끼리의 통신은 경로만 있으면 된다"고 적고 넘어갔다. 그 경로라는 게 뭔지, 패킷이 구글이든 본사 서버든 어떻게 찾아가는지를 봤다.

## 내 컴퓨터가 아는 건 두 가지뿐이다

패킷을 보낼 때 내 맥은 이것만 판단한다.

- 우리 집 기기인가 → 직접 준다
- 아닌가 → 공유기한테 준다

구글이 어디 있는지, 어떤 길로 가는지는 모른다. "우리 집이 아니면 공유기한테"만 안다.

```
목적지가 우리 집 프린터   →  직접 전달
목적지가 구글            →  공유기한테
목적지가 네이버          →  공유기한테
목적지가 회사 서버        →  공유기한테
```

이 "공유기한테"가 기본 게이트웨이다. 모르는 건 일단 여기로 보낸다.

## 다들 다음 한 칸만 안다

공유기도 구글이 어디 있는지 모른다. 공유기가 아는 것도 두 가지다. 우리 집 기기면 직접 주고, 아니면 통신사 장비한테 준다. 통신사 장비도 같은 식으로 다음 장비한테 넘긴다. 그렇게 계속 넘기다 보면 구글을 아는 장비에 도착한다.

```
내 맥 → 공유기 → 통신사 → 더 큰 통신사 → … → 구글
       "모르니까   "모르니까    "아, 구글은
        위로"       위로"       저쪽이야"
```

택배랑 같다. 동네 편의점은 부산의 그 집이 어딘지 모른다. "우리 동네가 아니면 집하장으로"만 안다. 집하장도 "부산 건 부산 터미널로"만 안다. 아무도 전체 경로를 모르는데 택배는 도착한다. 각자 다음에 누구한테 넘길지만 알면 되니까.

### 실제로 찍어보면 보인다

`tracert` 로 한 칸씩 넘어가는 걸 볼 수 있다. 윈도에서 `8.8.8.8` 까지 앞 6칸만 찍었다.

```
1    <1 ms    192.168.0.1       ← 집 공유기 (내 게이트웨이)
2     3 ms    1.227.x.x         ← 여기부터 통신사 소유
3    <1 ms    100.69.x.x        ← 통신사 내부
4     1 ms    10.62.x.x         ← 통신사 내부
5     2 ms    10.222.x.x
6     2 ms    10.222.x.x
```

**각 줄이 라우터 하나**다. 내 PC가 아는 건 1번뿐이고, 1번은 2번만 안다. 위에 쓴 "다음 한 칸만 안다"가 이렇게 찍힌다.

재밌는 게 두 개 보였다.

**3번 `100.64.0.0/10` 대역** — 통신사 전용 NAT 대역이다. [NAT](nat.md) 노트에 "NAT는 겹친다"고 적었는데 그게 여기 있다. 내 공유기가 한 번 NAT 하고 **통신사가 자기 망에서 또 NAT** 한다.

**4~6번 `10.x.x.x`** — 사설 대역이다. **통신사 내부 라우터들이 사설 IP를 쓴다.** 공인 IP는 아껴야 하는 자원이고, 라우터끼리 패킷 넘기는 데는 공인 IP가 필요 없으니까. [사설망](private-network.md) 노트의 "공인 IP를 아낄 수 있다"가 통신사 자신에게도 적용되는 셈이다.

```
집 안      192.168.0.x    사설
통신사 내부  10.x.x.x       사설      ← 여기도 사설이다
목적지     8.8.8.8        공인
```

### 위아래가 아니라 그물이다

위에 "통신사 → 더 큰 통신사"라고 적어놨는데, 그게 **끝까지 올라가면 정점이 있는 건 아니다.**

통신사끼리는 규모 차이가 있어서 계층처럼 보인다.

```
Tier 1   전 세계 망을 가진 소수. 서로 대등하게 교환 (돈 안 주고받음)
Tier 2   Tier 1 에 돈 내고 연결. 지역 규모 (한국 통신사들)
Tier 3   Tier 2 에서 받아 소매로 판매
```

아래쪽은 돈 내고 올라가는 구조라 계층이 맞다. 그런데 **맨 위 Tier 1 끼리는 서로 대등하게 연결한다.** 누가 누구 위가 아니라 "우리 서로 공짜로 넘겨주자" 관계다.

```
        ISP A ──── ISP B
          │    ╳    │
        ISP C ──── ISP D
```

**그래서 최상위가 없다. 인터넷에는 중심이 없다.** 계층을 따라 올라가면 정점이 아니라 대등한 그물이 나온다.

이게 설계 의도다. 중심이 있으면 거기가 죽으면 전부 죽는다. 일부가 끊겨도 다른 길로 돌아가도록 만든 거다. 위의 tracert 가 1→2→3→4 로 일렬로 보였지만 그건 **그때 고른 한 경로**고, 중간이 끊기면 다른 길로 간다.

## 라우팅 / 라우터 / 게이트웨이

| 단어 | 뭔가 | 택배로 치면 |
|---|---|---|
| 라우팅 | 다음에 누구한테 넘길지 정하는 일 | 배송 |
| 라우터 | 그 일을 하는 장비 | 집하장 |
| 라우팅 테이블 | 그걸 적어둔 메모 | "우리 동네면 직접, 아니면 집하장" |
| 게이트웨이 | 내 입장에서 밖으로 나갈 때 넘기는 첫 장비 | 우리 동네 편의점 |

"배송"이라는 서버가 따로 없는 것처럼 라우팅이라는 서버가 따로 있는 게 아니다. 패킷을 넘겨주는 장비들이 각자 라우팅을 한다. 라우터는 손으로 만질 수 있는 기계다.

- 집: 공유기 안에 라우터 기능이 들어 있다
- 회사: 전산실 랙에 꽂힌 라우터, L3 스위치
- 통신사: 통신사 건물(국사)이나 데이터센터에 있는 큰 라우터들. 인터넷은 결국 이런 장비 수만 대가 이어진 거다

## 라우터의 정의에는 조건이 둘이다

나중에 다시 보면서 정리한 건데, 라우터를 한 줄로 말하면 이렇다.

> **대역을 둘 이상 잇고, 패킷을 넘겨주는 장비**

조건이 **두 개**다. 처음엔 "대역 둘 이상"만 생각했는데 그것만으로는 부족하다.

```
① 대역을 둘 이상 가진다      양쪽에 발이 있어야 넘길 수 있으니까
② 넘기는 기능이 켜져 있다    꺼져 있으면 안 넘긴다
```

왜 ①이 필요한지는 ②에서 나온다. **다른 대역으로 넘기려면 그 대역에 발이 있어야 한다.** 발이 없으면 넘길 방법이 없다.

②가 빠지면 틀린다. 내 윈도 PC를 찍어봤더니 대역이 네 개였다.

```
이더넷                192.168.0.130
vEthernet (Default)   172.22.112.1
vEthernet (WSL)       172.30.64.1
vEthernet (NAT)       169.254.17.25
```

가상 어댑터 때문에 대역이 넷인데 **라우터가 아니다.** 포워딩이 전부 꺼져 있다.

```
> Get-NetIPInterface -AddressFamily IPv4

이더넷                             Disabled
vEthernet (Default Switch)         Disabled
vEthernet (WSL)                    Disabled
vEthernet (NAT-Switch)             Disabled
```

이더넷으로 들어온 패킷을 WSL 대역으로 넘겨주지 않는다. 네 대역이 **서로 격리된 채로 이 PC에 따로따로 붙어 있을 뿐**이다.

그래서 "대역 여러 개"는 **여러 망에 발을 담근 기기**일 뿐이고, 거기에 넘기는 기능이 켜져야 **망을 잇는 장비**가 된다.

## 게이트웨이는 장비 종류가 아니라 역할이다

공유기 하나를 두고 이름이 둘이다. 장비로서는 라우터고, 내 맥 입장에서는 게이트웨이다. 게이트웨이 장비를 따로 사는 게 아니라 내 바로 다음에 있는 라우터를 그렇게 부르는 거다.

누구 기준이냐에 따라 달라진다.

```
내 맥 ──▶ 공유기 ──▶ 통신사 라우터 ──▶ …
         ↑
         내 맥의 게이트웨이

         공유기 ──▶ 통신사 라우터
                    ↑
                    공유기의 게이트웨이
```

### 게이트웨이는 반드시 라우터다

이건 논리적으로 딱 떨어진다.

```
게이트웨이의 일 = 다른 대역으로 넘기기
넘기려면        = 양쪽 대역에 발이 있어야 함
양쪽에 발       = 라우터의 조건 ①
```

**게이트웨이가 라우터가 아닐 수는 없다.** 그래서 공유기는 "게이트웨이면서 라우터"다. 둘 중 하나를 고르는 게 아니다.

### 그래서 게이트웨이로 라우터를 정의할 수 없다

"라우터는 대역을 둘 이상 가진 게이트웨이다"라고 말해봤는데 틀렸다. 두 가지 이유로.

**순서가 뒤집혔다.** 게이트웨이가 이미 라우터니까, "대역 둘 이상인 게이트웨이"는 "대역 둘 이상인 라우터"가 된다. 동어반복이다.

**게이트웨이는 기준이 필요한 말이다.** 정의는 기준 없이 성립해야 하는데, 게이트웨이를 넣으면 "누구의?"가 빠진 채 남는다.

순서는 이렇다.

```
① 라우터      대역을 잇는 장비              (객관적 정의)
       ↓
② 게이트웨이   그 중 나에게서 한 칸인 것      (내 기준의 호칭)
```

①을 먼저 세우고 ②를 거기서 뽑아낸다. 반대로 하면 순환이다.

누가 물어보면 이렇게 답하면 된다.

> **라우터는 망을 잇는 장비, 게이트웨이는 그 중 내 출구.**

### 왜 명칭을 둘로 나눴나

같은 장비인데 왜 단어가 두 개인가. **다른 질문에 답하기 때문**이다.

```
"라우터"      이 장비가 뭐냐?        → 장비 분류     (객관)
"게이트웨이"   나는 어디로 넘기냐?    → 내 설정값     (상대적)
```

실용적인 이유가 있다. PC 네트워크 설정의 칸 이름이 "게이트웨이"다. "라우터"가 아니다.

```
"라우터 주소를 적으세요"     →  어느 라우터? 세상에 수백만 개인데
"게이트웨이를 적으세요"      →  "나에게서 한 칸인 그것" 으로 특정됨
```

내가 설정에 적어야 하는 건 "세상에 라우터가 있다"는 사실이 아니라 **"나는 어디로 넘기면 되나"** 다. 그 값을 가리킬 단어가 필요해서 게이트웨이를 쓴다.

반대로 장비를 살 때는 "라우터"가 맞다. "게이트웨이 한 대 주세요"는 이상하다 — 누구 기준인지가 안 정해지니까.

```
설정할 때      게이트웨이    (내 기준이 이미 정해져 있다)
장비 말할 때    라우터        (기준이 필요 없다)
```

참고로 "게이트웨이"는 네트워크 전용 단어가 아니다. **"서로 다른 체계를 잇는 출입구"** 라는 일반 개념이라 다른 데서도 쓴다. API 게이트웨이, 결제 게이트웨이 전부 "다른 쪽으로 넘어가는 문"이라는 같은 뜻이다. IP 라우팅에서는 그걸 "다른 대역으로 가는 문"으로 좁혀 쓰고, 정식 명칭이 `default gateway` 다.

## 내 맥의 라우팅 테이블

`netstat -rn -f inet` 으로 찍어보면 줄이 많은데 핵심은 두 줄이다. 내 IP는 `192.168.219.101` 이었다.

```
Destination        Gateway            Netif
default            192.168.219.1      en0      ← 아니면 공유기한테
192.168.219        link#11            en0      ← 우리 집이면 직접
```

- `192.168.219` → `link#11`: 목적지가 `192.168.219.x` 면 게이트웨이 안 거치고 와이파이(`en0`)로 직접 보낸다. `link#` 은 선에 바로 붙어 있다는 뜻이다
- `default` → `192.168.219.1`: 어느 줄에도 안 맞으면 공유기한테 넘긴다

위에서 말한 두 가지 판단이 그대로 표로 들어가 있다. [IP / 서브넷 / 포트](ip-subnet-port.md) 노트의 "같은 대역인지 판단"이 실제로는 이 표로 돌아가는 거다. 나머지 줄(MAC 주소가 적힌 것들)은 같은 대역 안에서 실제로 전달할 때 쓰는 건데 ARP에서 볼 거다.

## 라우팅 테이블은 다 있고, 넘겨주는 기능은 꺼져 있다

라우팅 테이블은 모든 기기에 기본으로 있다. 내 맥, 폰, 프린터 다 있다. 자기 패킷을 어디로 보낼지는 누구나 판단해야 하니까. 내 맥이 "우리 집이면 직접, 아니면 공유기" 하는 것도 라우팅이다.

대신 남의 패킷을 넘겨주는 기능은 기본으로 꺼져 있다. 내 맥은 자기 패킷만 보내고 남이 보낸 패킷이 오면 버린다. 라우터는 이게 켜져 있는 장비다. 리눅스에서 `ip_forward` 를 켜면 일반 서버도 라우터처럼 동작한다. Docker가 호스트에서 켜는 게 이거다.

그래서 라우팅 기능은 라우터라는 이름의 장비에만 있는 게 아니다.

| 장비 | 라우팅 |
|---|---|
| 라우터 | 본업 |
| 공유기 | 라우터 + 스위치 + NAT + DHCP + 와이파이를 한 상자에 넣은 것 |
| L3 스위치 | 스위치인데 라우팅도 함. 회사 전산실에 많다 |
| 방화벽 | 차단이 본업인데 라우팅도 함 |
| PC, 리눅스 서버 | 설정을 켜면 라우터 역할 가능 |

### 내 PC 가 이미 남의 게이트웨이다

"설정을 켜면 가능"이라고 적어놨는데, 알고 보니 **이미 그러고 있었다.**

내 게이트웨이가 나 자신이 될 수는 없다. 게이트웨이는 "나에게서 한 칸"이고 나는 0칸이다. `default` 가 나를 가리키면 패킷이 나한테서 나한테로 돌아 루프가 된다.

근데 **남에게는 된다.**

```
WSL 안의 리눅스 입장
  내 IP        172.30.64.x
  게이트웨이    172.30.64.1    ← 이게 내 윈도 PC 다
```

WSL 안에서 보면 내 PC가 게이트웨이다. 리눅스가 인터넷에 나갈 때 내 PC로 넘기고, 내 PC 가 공유기로 보낸다. WSL 안에서 `ip route` 를 찍으면 `default via 172.30.64.1` 이 나온다.

위에서 포워딩이 전부 `Disabled` 였는데 어떻게 되는 거냐 — **윈도는 가상 네트워크를 NAT 으로 따로 처리한다.**

```
> Get-Service WinNat, SharedAccess
WinNat        Running
SharedAccess  Running      ← ICS(인터넷 연결 공유)

> Get-NetNat
NAT-Swtich    10.0.0.0/24
```

넘기는 방식이 평범한 IP 포워딩이 아니라 NAT 이라 그 플래그에 안 잡힌다. 그러니 "포워딩 Disabled = 절대 안 넘긴다"로 읽으면 틀린다. **넘기는 경로가 여러 가지다.**

정리하면 같은 장비가 방향에 따라 역할이 다르다.

```
공유기 쪽으로는   일반 기기        (공유기가 내 게이트웨이)
WSL 쪽으로는      게이트웨이        (내가 WSL 의 게이트웨이)
```

"게이트웨이는 누구 기준이냐에 따라 달라진다"가 자기 PC 안에서도 성립한다.

## 라우터가 없는 망도 있다

대역이 하나뿐이면 라우터가 필요 없다. 라우터는 서로 다른 대역 사이를 이어주는 장비라서, 같은 대역 안에서는 "우리 집이면 직접"으로 끝난다. 이럴 땐 스위치만 있으면 된다. 스위치는 같은 대역 안의 기기들을 선으로 묶어주기만 하고 라우팅은 안 한다.

```
라우터 없는 망
  PC 192.168.0.10 ──┐
  PC 192.168.0.11 ──┼── 스위치
  서버 192.168.0.20 ─┘
  → 서로 직접 통신. 밖으로 나갈 출구가 없음
```

공장 라인에서 설비랑 PC 몇 대를 스위치 하나로 묶은 망, PC 두 대를 랜선으로 직접 연결한 경우 같은 게 그렇다.

처음엔 이게 폐쇄망인가 했는데 다른 얘기다.

| | 뜻 | 라우터 |
|---|---|---|
| 라우터 없는 망 | 대역이 하나뿐 | 없음 |
| 폐쇄망 | 인터넷(외부)과 연결이 끊긴 망 | 있을 수 있음 |

발전소 제어망 같은 폐쇄망은 보통 규모가 커서 대역을 여러 개로 나누고 그 사이를 라우터로 잇는다. 그 라우터들의 표에 인터넷으로 나가는 줄이 없을 뿐이다. 안에서는 라우팅하고 밖으로는 길이 없다.

```
폐쇄망
  대역 A ── 라우터 ── 대역 B
              │
              └── 라우터 ── 대역 C

  어느 라우터에도 "모르면 인터넷으로"라는 줄이 없음
```

라우터가 있냐 없냐는 망이 몇 개로 나뉘었냐로 정해지고, 폐쇄망이냐는 밖이랑 이어졌냐로 정해진다.

## 우리 망에 라우터가 있는지 보려면

내 기기 라우팅 테이블에서 `default` 줄을 본다.

```
netstat -rn | grep default
default   192.168.219.1   ...     ← 있음. 이 주소가 라우터(게이트웨이)
```

`default` 줄이 없으면 이 기기는 자기 대역 밖으로 나갈 길이 없다. 이 줄은 보통 DHCP가 IP를 줄 때 같이 알려준다. 와이파이에 붙기만 해도 게이트웨이가 자동으로 잡히는 이유다.

다른 대역이랑 통신해야 하는데 라우터가 없으면 셋 중 하나를 둔다.

- 공유기나 라우터 장비를 놓는다. 작은 망에서 제일 흔하다
- L3 스위치를 쓴다. 회사에서 층별, 부서별로 대역을 나눌 때
- 서버 한 대에 랜카드 두 개를 꽂고 포워딩을 켠다. 테스트 환경 같은 특수한 경우

장비를 놓은 다음에는 각 PC에 "모르면 이 장비한테"라는 `default` 줄(게이트웨이)을 알려줘야 한다. 장비만 있고 PC가 그 주소를 모르면 안 쓰인다.
