# 3단계: 글자 → 다음 글자 맞히기 (바이그램)

[토큰 노트](token.md)에서 LLM은 다음 토큰 맞히기라고 했다. 그걸 제일 단순하게 직접 만들어봤다. 바로 앞 글자 하나만 보고 다음 글자를 맞힌다.

실습 코드: [code/03_bigram.py](code/03_bigram.py)

## 바이그램은 이 글자 뒤에 뭐가 자주 왔나 세는 것이다

휴대폰 자동완성이랑 같다. "엄" 다음에 "마"를 자주 쳤으면 "엄"을 칠 때 "마"를 추천한다.

```
학습용 글: 엄마, 엄마, 엄지

엄 → 마  2번   →  67%
엄 → 지  1번   →  33%
```

글자 두 개(앞 글자, 다음 글자)씩 짝지어 세서 바이그램(bi = 둘)이다. 파이썬에서는 `zip(w, w[1:])`로 "엄마"를 `('엄','마')` 짝으로 묶고 `Counter`로 센다.

## 단어 짓기는 확률대로 주사위 굴려서 이어 붙이기다

끝말잇기처럼 글자 하나 뽑고, 그 뒤에 자주 왔던 글자를 또 뽑는다. 뽑을 땐 확률대로 주사위를 굴린다. 67%짜리가 자주 나오지만 33%짜리도 가끔 나온다.

어디서 시작하고 끝낼지 알아야 해서 단어 앞뒤에 `.`을 붙여서 센다.

```
학습용 글:  .엄마.  .마루.  .엄지.

.에서 시작 → 주사위: 엄 67% 마 33%  → 엄
엄 다음   → 주사위: 마 50% 지 50%  → 마
마 다음   → 주사위: .  50% 루 50%  → 루
루 다음   → 주사위: .  100%        → 끝

결과: 엄마루   ← 학습용 글에 없던 단어
```

"엄마"와 "마루"가 "마"에서 이어져서 새 단어가 생겼다. Claude가 답을 쓰는 것도 똑같다. 다음 토큰 확률 → 주사위 → 이어 붙이기 → 반복. 같은 질문에 답이 매번 조금 다른 게 이 주사위 때문이다.

## 글을 많이 보면 그럴듯해진다

영어 이름 32,033개로 똑같이 해봤다.

```
바이그램 (세서 뽑기)      아무렇게나 뽑기
jeriri                   hzezrocckqpdjrjwdrk
cende                    rgztrsjoctzmkshjfg
karnko                   fbtvipccvyeeb
jalynnal                 cw
evy                      rvm
```

표 하나로 키보드 막 친 것과 있을 법한 이름만큼 차이가 난다. 그래도 `h`, `dh`, `br` 같은 이상한 게 섞인다. 바로 앞 글자 하나만 보고, 그 전에 뭘 썼는지 기억을 못 하기 때문이다.

| | 아무렇게나 | 바이그램 | 진짜 LLM |
|---|---|---|---|
| 보는 것 | 없음 | 앞 글자 1개 | 앞에 쓴 글 전부 |
| 결과 | 키보드 막 친 것 | 그럴듯한데 가끔 이상함 | 자연스러움 |

4~6단계는 결국 앞을 더 많이 보게 만드는 과정이다.

## 세지 않고 학습해도 같은 표가 나온다

진짜 LLM은 세지 않는다. 앞을 많이 보게 되면 셀 경우가 너무 많아진다. 대신 [1단계](01-gradient-descent.md)의 학습과 [2단계](02-autograd.md)의 `backward()`를 쓴다.

```python
score = torch.zeros(2, requires_grad=True)   # [마, 지] 점수, 처음엔 똑같이
answers = [0, 0, 1]                           # 엄 다음 정답: 마, 마, 지
prob = score.softmax(0)                       # 점수 → 확률
loss = -prob[answers].log().mean()            # 정답에 준 확률로 벌점
loss.backward()                               # 경사는 컴퓨터가
score -= score.grad * 0.5                     # 반대로 고치기 (반복)
```

```
 0회: 마 50%, 지 50%, 벌점 0.693
 1회: 마 54%, 지 46%, 벌점 0.669
 3회: 마 60%, 지 40%, 벌점 0.647
10회: 마 66%, 지 34%, 벌점 0.637
50회: 마 67%, 지 33%, 벌점 0.637   ← 센 거랑 같다
```

아무도 67%라고 안 알려줬는데 벌점만 보고 고치다 보니 센 값에 도착했다. 사과값이 1000원에 도착한 것과 같다. 벌점이 0까지 안 내려가는 건 정상이다. 정답이 마일 때도 지일 때도 있으니 67%/33%가 최선이다.

| | 세기 | 학습 |
|---|---|---|
| 방법 | 짝 개수 세서 나누기 | 찍고 → 벌점 → backward → 고치기 |
| 결과 | 마 67%, 지 33% | 마 67%, 지 33% |
| 앞을 많이 보면 | 셀 경우가 너무 많아서 못 함 | 똑같이 됨 |

앞을 더 많이 보게 바꿔도 학습하는 방법은 이대로 간다.
