# 1단계: 틀린 만큼 조금씩 고친다 (경사하강)

[0단계](00-python-numpy.md) 끝에서 "정답에 확률을 덜 줬으면 표 숫자를 조금 고친다"고 했다. 그 "조금 고친다"가 뭔지, 그리고 처음에 미뤄둔 학습 vs 추론을 봤다.

처음엔 샤워 온도 비유에 공식, 표, 용어가 한꺼번에 나와서 이해를 못 했다. 업다운 게임 하나로 다시 보니까 바로 됐다.

실습 코드: [code/01_gradient_descent.py](code/01_gradient_descent.py)

## 학습은 업다운 게임이다

친구가 생각한 숫자를 맞히는 게임이다.

```
나: 50!   친구: 다운
나: 30!   친구: 업
나: 40!   친구: 다운
나: 35!   친구: 정답!
```

처음엔 답을 전혀 몰랐는데 틀릴 때마다 업인지 다운인지 듣고 고치기만 했더니 맞혔다. 모델도 똑같다. 숫자를 대충 찍고 시작해서, 틀리면 고치기를 반복한다.

```
대충 찍기 → 얼마나 틀렸나 보기 → 반대로 고치기 → 반복
```

많이 틀리면 많이 고치고 조금 틀리면 조금 고친다. 답이 90인데 10을 불렀으면 확 올리고, 88을 불렀으면 살짝 올린다.

## 코드로는 세 줄이다

사과 3개가 3000원일 때 사과 1개 값을 맞힌다.

```python
guess = 500                       # ① 대충 찍기
for i in range(10):
    diff = guess * 3 - 3000       # ② 얼마나 틀렸나
    guess = guess - diff * 0.1    # ③ 반대로 조금 고치기
```

`diff`가 업다운 역할이다. 마이너스면 모자라서 업, 플러스면 넘쳐서 다운. 빼기를 하니까 자동으로 반대 방향으로 고쳐진다.

```
500원 → 650 → 755 → 828 → 880 → 916 → 941 → 959 → 971 → 980
차이  −1500  −1050  −735  …                              −61
```

아무도 1000원이라고 안 알려줬는데 차이만 보고 고치다 보니 1000에 다가간다. 가까워질수록 고치는 폭도 작아진다.

## 한 번에 얼마나 크게 고칠지가 학습률이다

`0.1`이 "한 번에 얼마나 크게 고칠지"다. 이걸 학습률(learning rate)이라고 한다.

```
0.01  500 → 515 → 530 → 544 → 557 → …        한참 걸림
0.1   500 → 650 → 755 → 828 → 880 → …        차근차근
0.5   500 → 1250 → 875 → 1062 → 969 → 1016   왔다 갔다 하다 맞힘
0.7   500 → 1550 → 395 → 1666 → 268 → 1805   💥 갈수록 멀어짐
```

0.7은 "업!" 하니까 너무 올려서 더 멀리 넘어가고, "다운!" 하니까 너무 내려서 반대로 더 멀리 간다. 실제 LLM도 학습률이 너무 작으면 학습이 안 끝나고 너무 크면 망가진다.

## 숫자가 여러 개면 많이 들어간 쪽이 많이 고친다

사과값, 우유값을 둘 다 모를 때다.

```
영수증: 사과 2개 + 우유 1개 = 4000원
예측:   2 × 500 + 1 × 500 = 1500원  → 차이 −2500, 업!
```

업인 건 알겠는데 누굴 올리나. 조별과제 점수가 안 나오면 많이 맡은 사람이 많이 고치는 것처럼, 총액에 2배로 들어간 사과가 2만큼, 1배로 들어간 우유가 1만큼 고친다.

```python
apple = apple - diff * n_apple * 0.02   # 차이 × 개수
milk  = milk  - diff * n_milk  * 0.02
```

각 숫자가 "이 차이에 내가 얼마나 영향을 줬나"를 경사(gradient)라고 한다. 경사만큼 반대로 내려가니까 경사하강법이다. 숫자가 백만 개여도 하는 일은 같다.

## 데이터가 적으면 답이 여러 개라 못 정한다

영수증 한 장으로는 못 맞힌다.

```
사과 2개 + 우유 1개 = 4000원을 만족하는 답
  사과 1000, 우유 2000  ✅
  사과 1500, 우유 1000  ✅
  사과 2000, 우유    0  ✅
```

영수증을 한 장 더 주면 둘 다 만족하는 답이 하나뿐이다.

```
영수증 1: 사과 2 + 우유 1 = 4000
영수증 2: 사과 1 + 우유 3 = 7000

  1회: 사과  695, 우유  835
 10회: 사과 1175, 우유 1800   ← 사과가 잠깐 넘쳤다가
200회: 사과 1000, 우유 2000   ✅
```

LLM이 글을 엄청 많이 봐야 하는 이유가 이거다.

## 학습은 공부하는 때, 추론은 시험 보는 때다

| | 학습 | 추론 |
|---|---|---|
| 정답 | 있음 | 없음 |
| 숫자 고치기 | 함 | 안 함 |
| 하는 일 | 예측 → 차이 → 고치기 반복 | 예측 한 번 |
| 시간 | 아주 김 (큰 LLM은 몇 달) | 짧음 |

학습으로 찾은 사과 1000원, 우유 2000원을 고정해두고 처음 보는 장바구니를 계산만 하는 게 추론이다.

```
사과 4 + 우유 2 = 4 × 1000 + 2 × 2000 = 8000원
```

Claude나 ChatGPT를 쓰는 건 전부 추론이다. 대화하는 동안 모델 숫자는 하나도 안 바뀐다. [LLM과 토큰](token.md)에서 본 한계가 여기서 설명된다.

- 기억이 없다: 대화해도 숫자가 안 바뀌니 나를 못 배운다. 그래서 대화를 통째로 다시 넣는다
- 학습 이후 일을 모른다: 숫자를 고정한 뒤 생긴 일은 들어갈 방법이 없다

## LLM은 정답에 몇 %를 줬나로 틀린 정도를 센다

LLM은 숫자 하나가 아니라 확률을 내놓는다. 정답 토큰에 몇 %를 줬는지만 보고 벌점으로 바꾼다.

| 정답에 준 확률 | 벌점 |
|---|---|
| 100% | 0 |
| 90% | 0.1 |
| 50% | 0.7 |
| 10% | 2.3 |
| 1% | 4.6 |

정답에 준 확률이 낮을수록 벌점이 확 커진다. 이 벌점이 손실(loss)이고, 계산법 이름은 크로스 엔트로피다. 코드로는 `-np.log(p)` 한 줄이다.

장보기랑 바뀐 건 "틀린 정도"를 세는 방법 하나뿐이다.

| | 장보기 | LLM |
|---|---|---|
| 예측 | 총액 | 다음 토큰 확률 |
| 틀린 정도 | 몇 원 차이 | 정답에 준 확률로 매긴 벌점 |
| 고치기 | 영향 준 만큼 반대로 | 같음 |

학습이 잘 되고 있으면 벌점이 점점 줄어든다. 그래서 학습시킬 땐 이 벌점을 계속 지켜본다.
