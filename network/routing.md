# 라우팅

[NAT](nat.md) 노트에서 "사설 IP끼리의 통신은 경로만 있으면 된다"고 적고 넘어갔다. 그 경로라는 게 뭔지, 패킷이 구글이든 본사 서버든 어떻게 찾아가는지를 봤다.

## 내 컴퓨터가 아는 건 두 가지뿐이다

패킷을 보낼 때 내 맥은 이것만 판단한다.

- 우리 집 기기인가 → 직접 준다
- 아닌가 → 공유기한테 준다

구글이 어디 있는지, 어떤 길로 가는지는 모른다. "우리 집이 아니면 공유기한테"만 안다.

```
목적지가 우리 집 프린터   →  직접 전달
목적지가 구글            →  공유기한테
목적지가 네이버          →  공유기한테
목적지가 회사 서버        →  공유기한테
```

이 "공유기한테"가 기본 게이트웨이다. 모르는 건 일단 여기로 보낸다.

## 다들 다음 한 칸만 안다

공유기도 구글이 어디 있는지 모른다. 공유기가 아는 것도 두 가지다. 우리 집 기기면 직접 주고, 아니면 통신사 장비한테 준다. 통신사 장비도 같은 식으로 다음 장비한테 넘긴다. 그렇게 계속 넘기다 보면 구글을 아는 장비에 도착한다.

```
내 맥 → 공유기 → 통신사 → 더 큰 통신사 → … → 구글
       "모르니까   "모르니까    "아, 구글은
        위로"       위로"       저쪽이야"
```

택배랑 같다. 동네 편의점은 부산의 그 집이 어딘지 모른다. "우리 동네가 아니면 집하장으로"만 안다. 집하장도 "부산 건 부산 터미널로"만 안다. 아무도 전체 경로를 모르는데 택배는 도착한다. 각자 다음에 누구한테 넘길지만 알면 되니까.

## 라우팅 / 라우터 / 게이트웨이

| 단어 | 뭔가 | 택배로 치면 |
|---|---|---|
| 라우팅 | 다음에 누구한테 넘길지 정하는 일 | 배송 |
| 라우터 | 그 일을 하는 장비 | 집하장 |
| 라우팅 테이블 | 그걸 적어둔 메모 | "우리 동네면 직접, 아니면 집하장" |
| 게이트웨이 | 내 입장에서 밖으로 나갈 때 넘기는 첫 장비 | 우리 동네 편의점 |

"배송"이라는 서버가 따로 없는 것처럼 라우팅이라는 서버가 따로 있는 게 아니다. 패킷을 넘겨주는 장비들이 각자 라우팅을 한다. 라우터는 손으로 만질 수 있는 기계다.

- 집: 공유기 안에 라우터 기능이 들어 있다
- 회사: 전산실 랙에 꽂힌 라우터, L3 스위치
- 통신사: 통신사 건물(국사)이나 데이터센터에 있는 큰 라우터들. 인터넷은 결국 이런 장비 수만 대가 이어진 거다

## 게이트웨이는 장비 종류가 아니라 역할이다

공유기 하나를 두고 이름이 둘이다. 장비로서는 라우터고, 내 맥 입장에서는 게이트웨이다. 게이트웨이 장비를 따로 사는 게 아니라 내 바로 다음에 있는 라우터를 그렇게 부르는 거다.

누구 기준이냐에 따라 달라진다.

```
내 맥 ──▶ 공유기 ──▶ 통신사 라우터 ──▶ …
         ↑
         내 맥의 게이트웨이

         공유기 ──▶ 통신사 라우터
                    ↑
                    공유기의 게이트웨이
```

## 내 맥의 라우팅 테이블

`netstat -rn -f inet` 으로 찍어보면 줄이 많은데 핵심은 두 줄이다. 내 IP는 `192.168.219.101` 이었다.

```
Destination        Gateway            Netif
default            192.168.219.1      en0      ← 아니면 공유기한테
192.168.219        link#11            en0      ← 우리 집이면 직접
```

- `192.168.219` → `link#11`: 목적지가 `192.168.219.x` 면 게이트웨이 안 거치고 와이파이(`en0`)로 직접 보낸다. `link#` 은 선에 바로 붙어 있다는 뜻이다
- `default` → `192.168.219.1`: 어느 줄에도 안 맞으면 공유기한테 넘긴다

위에서 말한 두 가지 판단이 그대로 표로 들어가 있다. [IP / 서브넷 / 포트](ip-subnet-port.md) 노트의 "같은 대역인지 판단"이 실제로는 이 표로 돌아가는 거다. 나머지 줄(MAC 주소가 적힌 것들)은 같은 대역 안에서 실제로 전달할 때 쓰는 건데 ARP에서 볼 거다.

## 라우팅 테이블은 다 있고, 넘겨주는 기능은 꺼져 있다

라우팅 테이블은 모든 기기에 기본으로 있다. 내 맥, 폰, 프린터 다 있다. 자기 패킷을 어디로 보낼지는 누구나 판단해야 하니까. 내 맥이 "우리 집이면 직접, 아니면 공유기" 하는 것도 라우팅이다.

대신 남의 패킷을 넘겨주는 기능은 기본으로 꺼져 있다. 내 맥은 자기 패킷만 보내고 남이 보낸 패킷이 오면 버린다. 라우터는 이게 켜져 있는 장비다. 리눅스에서 `ip_forward` 를 켜면 일반 서버도 라우터처럼 동작한다. Docker가 호스트에서 켜는 게 이거다.

그래서 라우팅 기능은 라우터라는 이름의 장비에만 있는 게 아니다.

| 장비 | 라우팅 |
|---|---|
| 라우터 | 본업 |
| 공유기 | 라우터 + 스위치 + NAT + DHCP + 와이파이를 한 상자에 넣은 것 |
| L3 스위치 | 스위치인데 라우팅도 함. 회사 전산실에 많다 |
| 방화벽 | 차단이 본업인데 라우팅도 함 |
| PC, 리눅스 서버 | 설정을 켜면 라우터 역할 가능 |

## 라우터가 없는 망도 있다

대역이 하나뿐이면 라우터가 필요 없다. 라우터는 서로 다른 대역 사이를 이어주는 장비라서, 같은 대역 안에서는 "우리 집이면 직접"으로 끝난다. 이럴 땐 스위치만 있으면 된다. 스위치는 같은 대역 안의 기기들을 선으로 묶어주기만 하고 라우팅은 안 한다.

```
라우터 없는 망
  PC 192.168.0.10 ──┐
  PC 192.168.0.11 ──┼── 스위치
  서버 192.168.0.20 ─┘
  → 서로 직접 통신. 밖으로 나갈 출구가 없음
```

공장 라인에서 설비랑 PC 몇 대를 스위치 하나로 묶은 망, PC 두 대를 랜선으로 직접 연결한 경우 같은 게 그렇다.

처음엔 이게 폐쇄망인가 했는데 다른 얘기다.

| | 뜻 | 라우터 |
|---|---|---|
| 라우터 없는 망 | 대역이 하나뿐 | 없음 |
| 폐쇄망 | 인터넷(외부)과 연결이 끊긴 망 | 있을 수 있음 |

발전소 제어망 같은 폐쇄망은 보통 규모가 커서 대역을 여러 개로 나누고 그 사이를 라우터로 잇는다. 그 라우터들의 표에 인터넷으로 나가는 줄이 없을 뿐이다. 안에서는 라우팅하고 밖으로는 길이 없다.

```
폐쇄망
  대역 A ── 라우터 ── 대역 B
              │
              └── 라우터 ── 대역 C

  어느 라우터에도 "모르면 인터넷으로"라는 줄이 없음
```

라우터가 있냐 없냐는 망이 몇 개로 나뉘었냐로 정해지고, 폐쇄망이냐는 밖이랑 이어졌냐로 정해진다.

## 우리 망에 라우터가 있는지 보려면

내 기기 라우팅 테이블에서 `default` 줄을 본다.

```
netstat -rn | grep default
default   192.168.219.1   ...     ← 있음. 이 주소가 라우터(게이트웨이)
```

`default` 줄이 없으면 이 기기는 자기 대역 밖으로 나갈 길이 없다. 이 줄은 보통 DHCP가 IP를 줄 때 같이 알려준다. 와이파이에 붙기만 해도 게이트웨이가 자동으로 잡히는 이유다.

다른 대역이랑 통신해야 하는데 라우터가 없으면 셋 중 하나를 둔다.

- 공유기나 라우터 장비를 놓는다. 작은 망에서 제일 흔하다
- L3 스위치를 쓴다. 회사에서 층별, 부서별로 대역을 나눌 때
- 서버 한 대에 랜카드 두 개를 꽂고 포워딩을 켠다. 테스트 환경 같은 특수한 경우

장비를 놓은 다음에는 각 PC에 "모르면 이 장비한테"라는 `default` 줄(게이트웨이)을 알려줘야 한다. 장비만 있고 PC가 그 주소를 모르면 안 쓰인다.
