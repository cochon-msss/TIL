# OSI 7계층

지금까지 배운 IP·포트·TCP/UDP·HTTP가 각각 어디 들어가는지 꿰는 지도 같은 거다. 새로 외운다기보단 "그게 여기였구나" 정리하는 느낌.

## 왜 계층으로 나눴냐

통신이라는 큰 일을 역할별로 쪼개서 각 층이 자기 일만 하게 한 거다.

- 한 층을 바꿔도 다른 층은 그대로. (와이파이 -> 유선으로 바꿔도 위층 HTTP는 신경 안 씀)
- 문제 생겼을 때 "몇 계층 문제냐"로 나눠서 진단 가능

## OSI 7계층 (위에서 아래로)

이미 아는 거랑 붙여서 보면:

```
7. 응용(Application)    ← HTTP, HTTPS, DNS, FTP
6. 표현(Presentation)   ← 암호화, 인코딩 (SSL/TLS, 문자셋)
5. 세션(Session)        ← 연결 세션 관리
------------------------------------------------
4. 전송(Transport)      ← TCP, UDP, 포트
3. 네트워크(Network)     ← IP, 라우팅, 서브넷
2. 데이터링크(Data Link) ← MAC 주소, 이더넷, 스위치
1. 물리(Physical)       ← 케이블, 전기신호, 랜선
```

IP는 3계층, 포트/TCP/UDP는 4계층, HTTP는 7계층. 실무에서 자주 보는 건 1, 2, 3, 4, 7이고 가운데 5·6은 요즘 모델에선 응용에 뭉뚱그려진다.

## 캡슐화 - 층을 내려가며 옷을 껴입는다

`GET /index.html` 하나 보낼 때, 위층부터 아래로 내려가면서 각 계층이 자기 헤더를 하나씩 붙인다.

```
7 응용    : GET /index.html                    ← 보낼 데이터
4 전송    : [TCP헤더: 포트 443] + 데이터         ← 세그먼트
3 네트워크 : [IP헤더: 목적지 192.168.0.130] + 위  ← 패킷
2 링크    : [MAC헤더: 옆 장비 주소] + 위          ← 프레임
1 물리    : 010101... 전기신호로 쏨
```

택배로 치면 물건(데이터)을 상자에 넣고(TCP) -> 운송장 주소 붙이고(IP) -> 트럭에 실어서(MAC/물리) 보내는 거다.

방향 주의. 보낼 때(7->1 내려감)는 헤더를 붙이니까 점점 커진다(캡슐화). 받는 쪽은 정반대로 1->7 올라가며 껍질을 하나씩 벗긴다(역캡슐화). 그래서 작아지는 건 받는 쪽 얘기고, 보내며 내려갈 땐 붙여서 커진다.

이걸 알면 "한 패킷에 IP도 포트도 데이터도 다 있는데 뭐지?" 가 풀린다. 각각 다른 계층이 붙인 헤더다. IP는 3계층이, 포트는 4계층이 붙인 거.

## IP vs MAC (3계층 vs 2계층)

둘 다 주소인데 역할이 다르다.

- IP(3계층) = 최종 목적지. "저 멀리 그 집"
- MAC(2계층) = 바로 옆 장비까지. "다음 정거장(라우터/스위치)"

택배 최종 주소(IP)는 고정인데, 트럭이 정거장 거칠 때마다 "다음 어디로"(MAC)는 계속 바뀐다. IP는 안 변하고 MAC은 홉마다 바뀐다.

## OSI vs TCP/IP 모델

"요즘은 OSI 안 쓰고 TCP/IP 쓴다"는 말은 반만 맞다. 둘이 용도가 달라서 같이 살아있다.

- OSI 7계층 = 이론/참조용 지도. 개념 설명하고 "몇 계층 문제냐" 진단할 때 씀. (교육·면접에 자주 나오는 이유)
- TCP/IP 4계층 = 실제 인터넷이 돌아가는 실용 모델. 구현은 이걸로.

```
   OSI 7계층              TCP/IP 4계층
7 응용  ┐
6 표현  ├──────────→   응용 (Application)
5 세션  ┘
4 전송     ──────────→   전송 (Transport)
3 네트워크  ──────────→   인터넷 (Internet)
2 링크  ┐
1 물리  ┴──────────→   네트워크 액세스 (Network Access)
```

OSI 위 세 개(응용·표현·세션)가 TCP/IP에선 응용 하나로 뭉친다. 그래서 말할 땐 OSI 7계층으로, 실제 구현은 TCP/IP로 본다. 둘 다 알아두면 된다.

지금까지 배운 걸 두 모델로 정리하면:

```
HTTP        → OSI 7 응용    / TCP-IP 응용
TCP, 포트    → OSI 4 전송    / TCP-IP 전송
IP, 서브넷   → OSI 3 네트워크 / TCP-IP 인터넷
MAC, 랜선    → OSI 1~2      / TCP-IP 네트워크 액세스
```
